# 内部稿与外发稿规则

## 使用顺序

1. 正常生成和编辑的是**内部稿**。来源、逐字引文、证据状态和历史版本继续保留；内部 HTML 默认展示来源。
2. 在内部 HTML 右下角点“查看外部稿”。预览只展示面客内容，属于内部检查页面，尚不能直接当作已批准的交付物。
3. 在预览中点“外发检查”，确认结构、事实或规划口径、目标受众、分发范围、事实基线、本次版本和确认人；检查客户信息、案例、数字、图片、价格和强声明。
4. 检查通过才生成独立的外发 HTML、Markdown、Word。原有 `solution.*` 始终是内部稿；外发文件在 `solution.releases/<外发ID>/` 中。外发记录留在该目录的 `release-record.json`，不随外发文件下载。

九个逐项确认包括：无内部残留、无未批准内容、规划状态清楚、商务及责任风险边界可见、无自动化残留、结构一致、版本一致、声明强度未升级，以及问题→方案→价值链和必要论证完整。任何一项未勾选都不能生成外发文件。系统检查与人工确认并用；确认人需要按真实材料逐项核对，勾选本身不能证明事实准确或已经获得企业审批。

直接生成不要求先完成外发确认。资料不足的内部稿仍可继续编辑；有未解决内容时外发会停在检查结果，不把它润色成已实现的事实。当前 DSH 只有本地显式确认记录，不能据此声称完成企业级角色审批。

## 改写与检查

- 用目标读者的业务语言写判断、做法和结果；标题先讲结论。每块保留主张与支撑，避免抽象热词、生产流程说明和机械要点堆砌。
- 清理来源引用块、证据表格列、内部路径、证据编号、审核状态和工具痕迹。清理发生在独立外发文件的结构化数据中，不靠 CSS 隐藏。内部源稿和原文引文保持不变。
- 未解决的“待确认”“待核实”、凭证、内部文件路径、未核实的公开或用户补充痛点自动阻塞。强声明和价格须人工确认事实依据与批准口径；客户名称、案例、指标、图片授权由确认人检查。扫描不能保证识别所有敏感信息。
- “按项目确认”可作为明确适用条件；未知产品能力、客户事实和商业承诺不能靠换词放行。规划内容写明阶段或版本状态，不能改成已上线或标准能力。
- 外发结构按读者理解顺序检查，但不机械调整已确认的大纲。必要的范围、责任、风险、指标口径与保密边界保留；长论证可压缩并指向可读补充说明，不直接删掉论证链。
- 标题和段首应给出判断；每个内容块保留一个主张及支撑。不要堆“全方位”“一站式”等无依据的热词，不叙述生成过程或工具。长句可拆分，但不能割断逻辑。数字、对比和案例应有来源或标明假设。
- 评审状态、待裁决、内部版本差异、修改轮次、证据编号、来源路径、内部负责人、证据等级、置信度、账号密钥、未授权客户案例或指标、未批准价格承诺、内部成本利润及供应商信息、个人信息和内部组织架构均不得进入外发文件。自动扫描只能覆盖部分文字模式，其余由确认人核对。
- 未解决争议必须先裁决。“待确认”可在真实业务允许时准确改写为“按项目确认”或适用前提；假设转成前提条件，风险转成责任分工，不能用语气润色掩盖未知事实。
- 内部过程编号写成客户可验收的成果；排除清单写成适用范围，内部排期写成阶段路径，研发阶段说明真实版本状态，内部优先级写成客户关心的价值层级。“不承诺”可写成标准范围或定制服务边界，但不能删除限制。
- 简化时可以保留、压缩并给补充说明入口、在不升级声明强度的前提下改写，或把细节移到有入口的附录。只能删除纯背景且要在内部记录理由。问题→方案→价值、适用范围、风险假设、指标定义及权限保密边界必须保留。
- 声明强度只能保持或降低：可设计≠已实现、内部验证≠生产验证、按项目确认≠标准能力、规划中≠已上线、单场景验证≠全场景适用。
- 外发文件应核对目录、标题、版本和日期的一致性。若内部稿在预览后更新，旧预览不能发布；新外发需重新检查。

## 规则修改与回退

活动配置位于 `$DSH_HOME/wlyd-presales-editor/external-policy.json`；若未设置 `DSH_HOME`，默认位于 `~/.dsh/wlyd-presales-editor/external-policy.json`。首次预览时会复制随包默认规则。编辑 `version`、`blockedTerms`、`strongClaims` 或 `claimStrengthPairs` 后保存，**下次预览或外发立即生效，无需重启 DSH**。JSON 格式错误时停止外发，不沿用旧规则偷偷放行。也可通过服务端环境变量 `WLYD_PRESALES_EXTERNAL_POLICY` 指向另一份规则文件。

每次读取的规则按 SHA-256 摘要保存在同目录 `policy-history/`。从插件源码目录执行：

```sh
node bin/external-policy.mjs show
node bin/external-policy.mjs history
node bin/external-policy.mjs rollback <history 中的完整摘要>
```

规则回退只影响之后的预览与外发。已经生成的外发文件、其源稿版本、规则摘要和确认记录都保留原样。词表可频繁修改；凭证、内部路径、未解决状态和版本一致性等底线检查写在执行器中，修改它们需要代码评审和重新测试。
