# 售前方案幻灯片设计规则

本规则随插件分发，适用于插件生成的 HTML 幻灯片。内容是本项目按售前材料场景整理的原创检查规则。

## 内容先于版式

1. 一页只讲一个核心判断；标题说清结论，正文展示依据。
2. “客户痛点”和“解决方案”使用相同的 P1、P2 等编号。一个方案须回答其对应痛点，不把无关功能充作解法。
3. 客户问题与产品能力分别标出材料原文；来源不足就写“待确认”，不补造数值、客户案例、资质或收益。
4. 从能力或场景推断的问题标“资料推断·待确认”；公开行业资料补充的问题标“行业参考·待核实”。两者都不能写成当前客户已发生的事实，公开资料不能证明本公司的产品能力。
5. 用户在对话中补充的信息标为“用户本轮补充（待核实）”，业务负责人复核后才能成为对外事实。

## 面客表达

- 成稿的标题、导语、正文、流程节点、图形标签和结尾应让客户直接读懂：说业务情境、对应做法和适用条件，避免“本章”“模型判断”“请复核原文”等内部制作话语。
- 至少半数章节须有可核对来源支撑的实质正文；整稿只有待确认占位文案时停止交付，不能生成空白幻灯片。
- 证据不足时使用“待与贵方确认”等准确措辞，不把典型挑战写成该客户已经发生的问题。逐字引文、来源路径与证据状态保持原样，编辑话术不能改写事实。
- 内部 HTML、Markdown、DOCX 使用同一份可追溯 JSON；内部审核步骤留在编辑界面和知识提案中，不出现在封面。外发文件从指定内部修订版派生，按 `guides/external-release.md` 清理和确认，不附带内部 JSON、来源路径或证据状态。

## 页面组织

- 根据材料组织约 3—7 章；直接生成请求先交付初稿，明确要求调整结构时再让用户修改大纲，不为凑章节拆碎内容。
- 封面只放方案主题、副标题、企业与必要联系信息，不嵌入目录或内部复核标签；需要目录时单独成页。
- 先让观众看到问题，再看逐项回应；证据较长时拆页，不缩小字号硬塞。
- 内容短而主张明确时用大字主张页；步骤使用带节点的时间线；能力要点用有序清单；问题与做法用同编号连接图；截图用证据页。仅对真实数值使用大字指标，不为丰富画面编造数据。
- 同一语义页可按内容长度、信息数量、步骤数和来源是否存在，选择主张居中/带证据侧栏、能力分组/单列、流程横排/纵排/错列、图文并置/大图、叙述主张/编辑式分栏等构图；不要只交换左右栏。相邻同类页避免重复排法。同一份 `solution.json` 的选择须稳定，重新渲染和编辑保存后不随机跳版。
- 一份方案交替安排留白页、能力分组、流程、证据图和图表页；变化必须对应内容关系，品牌色、字号层级和边距保持一致。运行时用章节语义决定图标，用已有 P 编号生成问题—做法对照图，用步骤顺序生成流程轨道，用简短能力项生成关系图。没有图片、数据或对应关系时不造装饰。
- 当资料主要是段落和列表时也要明确变化：一段说明配简短要点用左右对比页；一段说明配长要点用整宽信息带；三个段落用主张加双列论证；单个步骤用大号里程碑，不画一条只有一个节点的流程线。对照关系的连续第二页和短步骤轨道可切换深色主题面，仍使用同一企业色和已知文字。
- 数值图表只在原文同一引文内同时出现类别或时间、数字和单位时使用。`bar` 表示同单位类别比较，`line` 表示按时间排序的趋势；不可把单个数字、估算值或不同口径硬拼成曲线。来源不足时采用定性流程、关系或文字页。
- 三列表格每页最多三组痛点—方案信息；编号列保持窄而稳定，长路径允许换行。
- 图像保留原比例，截图使用 `contain`，不裁掉真实界面；图片标题说明它证明什么。
- 留出标题、正文和页脚安全区。每页只强调一项关键信息，避免把所有文本做成同等权重。
- 所有元素都须留在 HTML 和 16:9 单页边界内。长段落、列表、表格行、痛点依据先分页；长路径强制换行；极端单页内容仍超量时只允许在页内区域滚动，不得越界或静默裁切。
- 标题层级固定为封面主标题最大、章节标题次之、内容页标题再次、卡片小标题最小；通过字号、字重和间距共同区分，不能只换颜色。
- 固定 16:9 页面在浏览器视口内完整缩放；大屏正文以至少 16px 为基准，信息过多时拆页，不为塞内容持续缩字号。
- 封面色彩随视觉方向变化，正文保持足够对比度；红色提示重点、蓝色提示对应做法。目录、章节、论点与来源、痛点对照采用各自的版式，避免重复的装饰卡片；内部稿来源保持可追溯，长文件名只显示可读名称，完整路径保留在悬停提示中。外发文件不包含路径。
- 封面可用克制的几何线条建立识别，线条不代表未给出的业务关系。正文图形只表达源稿已有的顺序、对应关系或已核实数值。

## 设计能力如何在插件中执行

从 `impeccable` 提取阅读层级与边界检查，从 `html-design-master` 提取成组变体与页面节奏，从 `guizang-ppt-skill` 提取编辑式排版与网格对照的高层方法，从 `ui-new` 提取视觉审查，从 `ui-ux-designer` 提取设计令牌与商业阅读路径，按售前幻灯片场景重写为以下规则。外部 Skill 不作为运行时依赖，也不直接复制模板、色板或提示词。

### 新方案的视觉方向

- 每次**新生成**依次轮换 `redline`（集团红蓝信息线）、`paper`（暖纸编辑式）、`night`（深色高对比）、`signal`（蓝色信号网格）四个原创方向；相邻生成不重复主风格。方向编号只保存在本机 DSH 状态中，不保存客户资料。有限方向循环后会复用，不能承诺永久唯一。
- 未指定主题时由方向选色；用户明确指定 `corporate`、`dark` 或 `elegant` 时保留其配色，仅在构图与细节上轮换。色彩是受控设计令牌，不随机生成十几种强调色。
- `solution.json` 保存设计方向和版式种子。相同 JSON 的内部稿、编辑后重渲染、外部预览和外发快照须保持同一视觉方向；旧 JSON 沿用原确定性版式，不在打开时突然换风格。
- 逐页先按结构判断：主张、痛点—做法、简短能力、长列表、单步或多步流程、真实图片、已核实数值图。只在相容页型之间使用设计种子选择变体，避免相邻页重复；没有图表数据就使用定性关系，不画假图。文字过长时先分页或回退较密的排版。

| 输入内容 | 插件版式决策 | 检查重点 |
| --- | --- | --- |
| 一条简短主张 | 留白主张页 | 标题先于解释，主张不得被来源注释抢焦点 |
| 有对应编号的痛点与做法 | 同编号关系图 | 左问题右做法，逐项对齐，不补造对应关系 |
| 2—4 条简短能力要点 | 能力关系图或分组 | 图标只帮助识别已有语义，过长则退回清单 |
| 3—4 个短步骤 | 顺序轨道 | 方向、节点顺序、阅读顺序一致；长步骤退回列表 |
| 可核实的同口径数字 | 比较图或时间趋势图 | 保留数值、单位、原始来源；无数据则不画数值图 |
| 截图或较长说明 | 图片证据页或编辑式分栏 | 图片不裁切，文字分级，必要时拆页 |

- 品牌色、文字色、边距和字号由同一套主题令牌控制；不同页型可以变化构图，不随意更换品牌语言。正文、次级说明、页脚和强调文字在对应底色上按普通文字至少 4.5:1 检查。
- 每页先看标题、主张、证据的阅读顺序；只给一处最高视觉权重。短句优先，卡片不是默认容器。使用图形时要能回答“这表示什么关系”；答不出就只保留文字。
- 交互控件提供可见焦点和足够点击区域。用键盘及窄屏检查导航；放不下的正文先拆页，不为了视觉整齐删除事实或缩成小字。
- 生成后按层级、对比度、排版、间距、组件状态、页内边界六项核对。自动测试覆盖主题文字对比度、版式选择和产物内容保留；视觉观感仍须逐页人工评审。

## 交付检查

- 浏览 HTML 逐页检查页面和内容区域的横纵溢出、表格可读性、来源路径和编号对应关系；桌面与窄屏都要看，打印页不应丢内容。
- 检查内容块是否真的支持本页标题；一个可提炼的论点可用大字叙述页，信息较多时改用段落、要点或步骤，不用空白卡片凑版面。
- 图表逐项核对类别、数字、单位、时间顺序和原文引文；HTML 编辑数据后须显著标待确认，Markdown/Word 用同源表格保留数值和来源。
- 浏览器演示可用上一页、下一页、四个方向键、PageUp/PageDown、空格、Home 和 End；打印时应输出全部页面。
- HTML 是当前可演示产物，Markdown/Word 是可编辑源稿。当前插件不生成可编辑 PPTX；若以后需要 PPTX，应单独设计并验证导出保真。
