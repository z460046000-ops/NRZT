# 售前方案写作规则

本规则从人工制作的 CallWan 企业增长方案、协同工作台方案中抽取**组织方法**。样本里的数字、功能、案例和承诺不是通用事实；生成任何新方案都须重新核对当前授权材料。

## 按材料选择叙事

- 企业增长/营销：背景与机会 → 目标客户的典型挑战 → 问题对应的业务链路与做法 → 平台支撑 → 实施与服务。能力页应说明从内容、触达到线索与复盘的因果关系，不把功能名排成目录。
- 企业协同/工作台：业务背景 → 客户问题与逐项对应的做法 → 人机协同机制和能力 → 典型落地场景 → 当前阶段与合作边界。产品处于试点或能力建设中时，明确区分已具备、试点中与规划中。
- 章节由材料决定，通常 3—6 章。封面只承载名称、主张、版本等必要信息，目录在后续页面；同一章可以有若干张页面，不为凑页数重复观点。

## 事实与表达

1. 每条挑战都要对应具体做法，并解释该做法如何回应挑战。无法建立对应关系时，分别写成待核实的典型挑战和已确认能力，不硬凑配对。
2. 初次接触客户，只写“典型挑战”“适用场景”，不声称客户已经遇到该问题；深入接触时，客户现状必须来自客户明确提供的资料。
3. 企业能力、数字、客户案例、价格和服务承诺必须由当前产品资料逐字支撑。来自公开搜索的材料只可补充行业背景或典型问题，标记“待核实”，不能替代企业能力依据。
4. 以客户能理解的业务结果和运行机制组织内容。API、组件名和架构术语仅在解释实施边界时出现，不把代码、接口目录或原始材料塞进正文。
5. 资料缺口不等于整稿停止。先交付已核实章节形成可编辑初稿；对缺失章节点名说明，让用户在对话里补充，或选择公开检索。补充后生成新版，旧版保留。完全没有有据正文时拒绝空稿。
6. 每章优先写 2—4 个有信息量的段落、要点或步骤。所有入稿事实保留准确来源与连续原文引文；逐字校验失败时重试该章，仍失败则保留待确认并在对话中说明。
7. 在事实范围内润色，不添加材料没有的能力、收益、因果或趋势判断。站在客户视角，先说客户遇到的具体情况，再说产品能做什么、怎样做。标题只表达一个判断，尽量控制在 8—18 字；导语不超过两句，正文每段以 1—2 个短句为主，一句只讲一件事。长内容拆成有实质信息的要点，不靠删掉适用条件换取简短。
8. 去掉“AI 正在重构一切”“未来竞争的关键”“赋能增长”“打造全链路闭环”“显著提升”等没有具体证据的套话，也避免连续堆叠三四个抽象名词。优先用资料里的业务动作和对象：谁处理线索、在哪一步记录、客户能看到什么。不要机械重复“首先/其次/最后”，也不要把营销形容词当作事实。原文引文和来源保持逐字不变。

示例：不要写“增长经营正从流量指标走向全链路闭环，构建内容、互动、线索和转化数据资产”；若材料确有对应能力，可写“您可以在同一处查看内容投放、客户互动和线索跟进记录。团队据此判断下一步该跟进谁。”具体能力仍须以本次材料为准。

## 交付检查

- 核对背景、挑战、做法、场景和边界的前后关系，以及标题与正文是否一致。
- 未完成章、待核实公开信息和用户补充事实在内部稿中可见；不得把它们伪装成已完成的对外方案。
- JSON、HTML、Markdown、Word 共用同一版本的章节结构；人工编辑后按现有版本机制同步生成。

## 文案能力与样式能力分开

- 文案能力负责叙事、事实范围、客户视角、句长和校对状态；`wlyd-presales-copywriting` 是独立的运行时 Skill，`src/writing-rules.js` 将同一标准注入大纲、整稿及补章调用，不再增加一次纯润色模型请求。
- 样式能力由 `wlyd-presales-html-ppt` 与确定性渲染器负责。字体层级、内容图示、分页和按内容选择的整稿统一风格不随文案改动重新随机选择。

## 从两个指定 Skill 提炼的表达标准

方法来源：[edu20260724](https://skillhub.cn/skills/user_d5e16fee/edu20260724)（SkillHub 包 1.0.0）与 [Humanizer](https://skillhub.cn/skills/clawhub_biostartechnology/humanizer)（SkillHub 包 1.0.0，正文标注 3.0.0，上游 blader/humanizer）。分发包收录本项目的售前适配规则，不复制高校折页模板或可选付费服务。

- 从具体背景写起，写清角色和动作。能力通过真实场景说明，价值通过运行机制解释；没有数字依据时不编效果数字。
- 每句话增加信息。合并重复内容，删除无信息的铺垫、总结、副标题复述；不用机械排比、强行三段式、“不是X而是Y”或匿名权威撑起观点。
- 采用简短、专业、自然的客户语言；适用条件、数字、名称、日期、承诺范围和连续原文引证不能在润色时丢失或变强。
- 对照用户人工样本控制句长和用词，同项目的不同产品突出各自场景。四字对仗仅可选；保留售前问题分析，不强套高校折页“只写正面”和固定页数。

## 校对状态独立于正文

正文不出现“待与贵方确认”“待确认”等制作提示。原提示及其位置保存在内部 JSON 的 `copyReview` 中：字段路径、当前文字、原文字、原因、pending/confirmed 状态及确认版本。典型挑战仍使用“可能”“典型”等自然限定，移除制作标签不会把推断变成客户事实。

内部稿及登录后的外部预览中，待校对文字显示点状下划线，点击或按 Enter 打开准确字段。纯占位句保存原文字，显示仅供编辑的“点击补充内容”；不当作正式正文。表单可改稿并明确勾选“此处已校对”，保存时同步 HTML/JSON/Markdown/Word。只修改不勾选，状态仍 pending；已确认内容再次改动，校对重新失效。空占位不能直接确认成有据正文。

外发下载及打印不显示下划线和编辑入口，外发前仍列出带位置的校对问题，支持确认当前列表继续，确认记录绑定版本。产品事实的知识变更仍须独立提交审核；材料校对或外发确认不自动发布企业知识，也不自动把数据依据改为 verified。
