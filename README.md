# DSH 售前解决方案插件

`@wlyd/dsh-presales-solution` 是运行在 DeepSeek Harness（DSH）中的售前内容生成插件。它把企业资料、项目知识和可核对的公开背景整理为**面向客户的解决方案初稿**，并输出可编辑的 HTML 幻灯片、Markdown、Word 和结构化 JSON。目标不是机械复述资料，而是围绕“背景 → 客户挑战 → 对应做法 → 业务价值 → 适用边界”，按证据组织营销叙事。

本文对应 **0.8.8** 分发包。初稿仍需业务人员核对，尤其是客户现状、能力承诺和对外使用范围。

## 运行模型

插件把入口选择、事实判断、语言生成和确定性校验分开：

```text
用户请求
  → 确定性路由（产品名、接触阶段、显式材料）
  → 授权资料读取 / 本地提取 / 必要时公开检索
  → 资料清洗与优先级排序
  → 痛点—做法证据判断与大纲
  → 模型撰写章节正文
  → 引文、可读性、空稿和面客措辞校验
  → solution.json → HTML / Markdown / DOCX
  → HTML 编辑 → 新修订版 → 同步重渲染
```

| 入口 | 路由行为 | 用户何时参与 |
| --- | --- | --- |
| “给我一份 CallWan 的产品售前解决方案” | 按产品名查当前账号可见、项目已绑定的知识库；不可读时尝试公开检索，直接生成初稿 | 缺产品名、同分匹配多个不同知识库，或证据不足以形成可用稿时提问 |
| “给我一份深入接触版……” | 与上面相同，但按深入接触阶段组织叙事；未指定时默认初次接触 | 同上 |
| `材料=/绝对路径` 或 `材料=平台` | 明确材料范围，先给可调整大纲，再生成正文 | 可改标题、合并、增删、排序；自然语言确认即可 |
| `/presales /绝对路径` | 已有会话中的命令入口 | 在空白 Web 会话中优先使用普通文字入口 |

默认营销大纲约 3—6 章；调整时允许 2—8 章。章节数由资料和场景决定，不固定为 10 章。技术接口文档是能力证据，不应直接成为面客目录。无资料时不会要求用户先上传路径；若既无可读知识又无可靠公开信息，则说明缺口并停止交付，不伪造产品能力。

## 生成逻辑与质量门槛

1. **资料可读性。** 本地支持文件、目录和 ZIP；从 Markdown、TXT、CSV、JSON、HTML、DOCX、PDF、PPTX 提取文字，图片仅登记为素材。先清除 HTML 的样式、脚本、代码和明显 PDF 乱码，再截取可读正文，避免 CSS 挤占业务内容。扫描版 PDF 暂无 OCR。
2. **资料权重。** 产品介绍、售前和营销材料优先承载面客叙事；接口、配置等技术材料用于验证能力与边界。内容中台读取须先核对当前项目与知识库绑定，再读取当前账号可见的文档；服务端仍作最终权限校验。每篇上限 20 MB，每轮上限 100 MB / 400 篇。
3. **问题与方案对应。** 资料明确写出客户问题时提取原有关系；只给出场景和能力时，可以提出“典型挑战”的候选表述，但保留待确认状态。每组关系都要有痛点、对应做法及两侧原文引文，独立复核是否处于同一场景、做法是否直接回应问题。没有可靠关系时可保留空数组，不能编造配对。
4. **公开资料补充。** 有 `web_search` 且内部证据不足时，可查询行业或场景背景。查询词不带企业资料原文或客户名；结果最多保留 5 条及 URL、时间、摘要。公开信息只用于行业问题或趋势，不用来证明本企业产品能力、客户收益或交付承诺。
5. **大纲与正文。** 明确提供材料时先展示大纲，可说“第 2 章改为实施路径”“合并第 2、3 章”“就按这个生成”。正文由当前 DSH 模型根据清洗后的资料生成；长输出被截断时逐章重试。模型不可用会报错，不以模板占位稿代替正文。
6. **交付前阻断。** 引文必须逐字出现在对应来源中，且来源属于该章；代码、乱码和不可读片段被拒绝。段落、列表和步骤都按实际文字检查；少于一半章节有实质内容时停止输出，避免四章中只有一章有内容或整稿全是“待确认”。少量真实缺口可以保留为待确认。

`wlyd_solution` 的结构化输入必须含 `pain_solution_links`，没有可靠配对时传 `[]`；`wlyd_platform_generate` 必须接收已确认的 `outline_headings`，并核对返回章节与大纲一致。这些是工具契约，不靠提示词单独约束。实现入口见 `src/router.js`、`src/content.js`、`src/source-quality.js` 和 `src/index.js`。

### 版式选择与图表

HTML 根据章节语义和内容块选择主张、能力、流程、证据、对照或数据图表页；同类页面有不同构图，连续页面避免重复。封面和章节页也有节奏变化。选择由方案标题、章节和页序确定，同一份 JSON 重新渲染会得到相同版式，不靠随机颜色制造差异。三套配色仍可选，但默认沿用企业红蓝主题。

`chart` 内容块只接受 2—6 个同单位数据点，支持类别比较（`bar`）和按时间排列的趋势（`line`）。标题、类别、数字、单位及逐字引文保存在 `solution.json`；自动生成时还核对引文是否属于该章原始资料。任何数字或标签不在同一段引文中，就丢弃该图表。资料只有定性描述时使用流程或问题—做法关系图，不补造统计。直接调用 `wlyd_solution` 的调用方仍须核对传入的来源路径确实指向原始材料。

HTML 负责图形表达；Markdown 和 Word 把同一图表数据输出为可审阅的表格并保留来源。HTML 编辑器可改图表标题、单位、标签和数值；改动数据后，所有格式都标记“数据待确认”，原始引文继续保留供审核。平台生成的纯 Markdown 若没有可核对的原始数字引文，不会自动转成图表。

## 面客话术与事实边界

| 规则 | 处理方式 |
| --- | --- |
| 以客户能理解的收益、场景和步骤表达 | 生成提示和写入 JSON 前的措辞转换共同约束标题、导语与正文；“待人工复核”等内部制作语改为面客说法 |
| 客户痛点不是已核实事实时 | 用“典型挑战”“可能”“待与贵方确认”等语气，保留 `inferred`、`public_unverified`、`user_unverified` 等依据状态 |
| 痛点与做法前后对应 | 每条关系同时保存两侧来源；不能从一个行业痛点直接推出本产品一定解决，也不能把功能清单冒充客户问题 |
| 不升级声明强度 | 不凭空写价格、指标、资质、案例、效果保证、合同或实施周期；没有证据的收益只能写为待验证目标 |
| 保留可追溯性 | 原文引文、来源路径和证据状态不做“润色”；所有导出从同一 `solution.json` 渲染 |
| 封面与演示页面 | 封面只放主题和必要抬头，目录单独成页；主标题、章节标题、内容标题和注释有层级；长内容拆页并防止越界 |

这里的“面客措辞”是**生成约束**，不等于正式外发审批或脱敏。HTML 的“隐藏来源”仅控制当前页面和打印的显示；JSON、Markdown、Word 中的来源仍在。发送给客户前应人工确认事实、客户名称、商务信息、图片授权和适用版本。本分发包不包含独立的外发稿审核与脱敏流程。

## 安装与配置

前提：Node.js 22+、可正常启动的 DSH、当前会话可用的模型服务；安装依赖时能访问 npm 软件包源。将 `dist/wlyd-dsh-presales-solution-0.8.8.tgz` 放到本机，执行：

```sh
dsh plugin --profile web add "/绝对路径/wlyd-dsh-presales-solution-0.8.8.tgz"
dsh plugin --profile web list
dsh web
```

若 Web 已启动，先在该终端用 Ctrl+C 停止，再重新运行 `dsh web`。DSH 仓库开发环境可将上述 `dsh` 换成 `pnpm dsh`。插件通过 `cordis.patch.yml` 注册到 web profile，安装后应在列表中看到 `@wlyd/dsh-presales-solution@0.8.8`。浏览器使用启动终端给出的地址和认证方式；直接把未认证的 `127.0.0.1` 结果链接粘到另一个浏览器，可能得到 401。

内容中台由 **运行 DSH 的服务端**配置：

| 环境变量 | 用途 |
| --- | --- |
| `WLYD_PLATFORM_BASE_URL` | 内容中台地址；未设置时使用代码内默认地址 |
| `WLYD_PLATFORM_EMAIL` / `WLYD_PLATFORM_PASSWORD` | 平台登录账号 |
| `WLYD_PLATFORM_TENANT_ID` | 当前租户 |
| `WLYD_KNOWLEDGE_PROPOSAL_URL` | 可选：知识修改的待审核提交接口 |
| `WLYD_KNOWLEDGE_API_TOKEN` | 可选：该接口的服务端令牌 |

凭证仅放服务端环境或 `$DSH_HOME/.env`，不要写入对话、前端、分发包或 Git。接收方需要自己的合法账号与项目授权；租户测试账号的联调结果不代表每位用户都有相同权限。

### 最短验证路径

在 DSH Web 新建会话输入“给我一份 CallWan 的产品售前解决方案”。应看到资料检索和正文生成；若无权限或模型配置，应收到具体错误，而不是空白幻灯片。要验证本地材料入口，可准备一份包含产品能力和适用场景的 Markdown 文件，然后输入 `用材料=/实际绝对路径 生成售前解决方案`。先修改或确认大纲，再检查最终每章是否有可读正文、依据与适用边界。

## 产物、编辑与知识同步

每轮产物独立保存在 DSH 会话工作目录的 `presales-runs/<时间>-<随机码>/`：

| 路径 | 作用 |
| --- | --- |
| `analysis/materials.json`、`analysis/corpus.md` | 材料清单、提取状态与可读文字 |
| `research/public-sources.md` | 使用公开检索时的 URL、时间与摘要 |
| `solution.json` | 唯一结构化源稿，含稳定内容 ID、来源与编辑版本 |
| `solution.html` | 16:9 可演示、可在授权入口编辑的 HTML；浏览器可打印为 PDF |
| `solution.md`、`solution.docx` | 与当前 JSON 同步生成的阅读和交付稿 |
| `solution.versions/` | HTML 每次保存后的历史快照 |
| `solution.knowledge-proposals/` | 涉及事实的编辑所提交的待审核记录 |

结果消息提供结构预览、HTML 编辑入口和 Word / Markdown / JSON 下载。先完成 DSH Web 认证，再在同一浏览器打开。HTML 可切换逐页演示和“隐藏来源”；该按钮不删底层证据。HTML 编辑保存后生成新修订版，并从 JSON 重渲染三种格式；并发旧窗口会提示刷新，避免覆盖新版。离线双击 HTML 只能预览和打印；在 Word 或 Markdown 中直接修改不会反向同步。

编辑产品事实时可勾选“提交知识审核”。插件保存变更和来源，并尝试发到配置的审核接口；未配置时状态为 `awaiting_knowledge_api`，**不代表已经入库**。知识事实须确认后再入库，方案措辞修改不会自动覆盖知识。接口约定见 `guides/knowledge-api-contract.md`，历史记录可用 `node bin/submit-knowledge.mjs "/方案所在目录" solution` 重试。

HTML 设计规则见 `guides/slide-design.md` 和随包 Skill `skills/wlyd-presales-html-ppt/SKILL.md`。渲染器按内容选择主张、问题与做法、流程、能力、证据等页型；参考设计方法已抽象为本项目规则，不依赖外部 Skill 运行。极端长内容和打印效果仍应逐页复核。当前没有可编辑 PPTX 导出；PDF 是浏览器打印能力。

## 工具与边界

| 工具 | 职责 |
| --- | --- |
| `wlyd_ingest` | 读取本地材料，提取可读文字和图片清单 |
| `wlyd_solution` | 验证结构化方案并写出 JSON、HTML、Markdown、DOCX |
| `wlyd_platform_setup` | 创建项目、绑定知识库并上传 1—10 个文件 |
| `wlyd_platform_upload` | 向已绑定知识库上传工作区文件并查询解析状态 |
| `wlyd_platform_generate` | 按已确认大纲使用平台资料生成 |

上传时文本文件直接上传，DOCX / PDF / PPTX 先提取为 Markdown；图片和 ZIP 不作为平台上传件。远程链接和聊天附件尚未作为本地材料入口接入；扫描 PDF 暂无 OCR。分发包不包含材料、会话数据或凭证。手工修改 `solution.json` 后可用 `bin/render.mjs` 离线重渲染，但该操作不产生 HTML 编辑版本，也不提交知识审核。

## 排错与验收

| 现象 | 先检查 |
| --- | --- |
| 没有 `/presales` | 是否安装到 `web` profile、列表有无插件、Web 是否重启；空白会话先用普通文字触发 |
| 知识库不可读或上传失败 | 平台账号、租户、项目绑定、文档解析状态和当前账号权限；服务端授权不能靠插件绕过 |
| 方案为空或大多是待确认 | 当前模型是否可用，材料是否有可读正文；质量门槛会阻断全占位或不足半数实质章节 |
| HTML / 下载链接返回 401 | 在同一浏览器完成 DSH Web 认证，并确认 Web 进程仍运行 |
| `awaiting_knowledge_api` | 方案已保存，知识审核接口尚未配置或尚未完成提交 |
| `Cannot read properties of undefined (reading 'prepare')` | DSH 宿主工具运行时需包含 `packages/core/tools/src/index.ts` 的调度器标识修复；只重装插件无效 |

在插件源码目录执行最小回归与打包：

```sh
npm ci
node --test test/*.test.mjs
node test/selftest.mjs /tmp/dsh-presales-selftest
mkdir -p dist
npm pack --pack-destination dist
```

自动测试和渲染自测只覆盖代码契约；真实账号权限、模型质量、公开检索准确性、复杂 PDF 和客户可用性仍需在目标 DSH 环境验收。`npm pack` 包含 README、源码、指南、Skill 和 DSH 挂载声明，不包含 `node_modules`、客户材料或密钥。
