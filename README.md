# DSH 售前解决方案插件

`@wlyd/dsh-presales-solution` 是运行在 DeepSeek Harness（DSH）中的售前内容生成插件。它把企业资料、项目知识和可核对的公开背景整理为**面向客户的解决方案初稿**，并输出可编辑的 HTML 幻灯片、Markdown、Word 和结构化 JSON。目标不是机械复述资料，而是围绕“背景 → 客户挑战 → 对应做法 → 业务价值 → 适用边界”，按证据组织企业增长或协同等售前叙事。

本文对应 **0.9.28** 分发包。内部稿保留来源供编辑与核对；独立外部稿按面客话术预览，完成外发检查后生成 HTML、Markdown、Word 文件。客户现状、能力承诺和对外使用范围仍需业务人员核对。

## 两部分能力

- **文案**：独立的 `wlyd-presales-copywriting`，抽象 EDU 产品宣传与 Humanizer 方法，实际约束大纲、整稿和补章。开篇交代产品、对象与要解决的问题；营销方案优先覆盖有据的环境与趋势、现状挑战、总体方案、平台能力、实施服务和公司介绍。痛点章深入讲问题名、真实工作场景与造成的麻烦；方案章只简要回扣痛点，重点讲对应做法。短句不能省掉读者需要的场景和因果。
- **样式**：`wlyd-presales-html-ppt`、`wlyd-presales-design-master`、`wlyd-presales-huashu-design` 与 HTML 渲染器按内容选择整稿统一风格，通过标题层级、构图、流程和图表体现主次。

话术规则参考用户确认稿的组织方式：目录区分章节与主题，挑战说“问题名、实际表现、造成的麻烦”，场景说“要做的事、做法、客户看得到的结果”。样本里的数字、产品功能和服务承诺只属于原稿，不会转成其他项目的事实。四个衔接环节若在本轮材料中明确出现，HTML 会突出原文关键词；较长单句不再作为整段大字主张。

### 点击正文校对

正文里的“待与贵方确认”等提示移入内部 JSON 的 `copyReview`。内部稿和外部预览用点状下划线表示待校对文字，点击进入对应编辑项，也支持键盘 Enter。空占位仅在编辑预览显示“点击补充内容”。

改稿后可勾选“此处已校对”并保存；不勾选则保留校对状态。已校对内容再次修改会重新出现下划线。保存同步 HTML、JSON、Markdown 和 Word，事实变更独立提交知识审核。下载外发稿和打印不显示编辑标记；外发前列出问题位置，可确认当前列表继续，内部保留与版本绑定的记录。

## 运行模型

插件把入口选择、事实判断、语言生成和确定性校验分开：

```text
用户请求
  → 确定性路由（产品名、接触阶段、显式材料）
  → 授权资料读取 / 本地提取 / 必要时公开检索
  → 项目记忆召回（有项目授权时，与资料检索并行；失败不阻断）
  → 资料清洗与优先级排序
  → 痛点—做法证据判断与大纲
  → 模型按章撰写正文（最多三章并行）
  → 引文、可读性、空稿和面客措辞校验
  → solution.json → HTML / Markdown / DOCX 初稿
  → Word 初稿确认（用户明确要求跳过时直接交付）
  → HTML 编辑 → 新修订版 → 同步重渲染
```

| 入口 | 路由行为 | 用户何时参与 |
| --- | --- | --- |
| “给我一份 CallWan 的产品售前解决方案” | 按产品名查当前账号可见、项目已绑定的知识库；不可读时尝试公开检索，直接生成初稿 | Word 初稿出稿后可确认、编辑或补充；明确说“不要确认，直接出最终产物”时跳过确认 |
| “给我一份深入接触版……” | 与上面相同，但按深入接触阶段组织叙事；未指定时默认初次接触 | 同上 |
| `材料=/绝对路径` 或 `材料=平台` | 明确材料范围，先给可调整大纲，再生成正文 | 可改标题、合并、增删、排序；自然语言确认即可 |
| `/presales /绝对路径` | 已有会话中的命令入口 | 在空白 Web 会话中优先使用普通文字入口 |

默认售前大纲约 3—6 章；调整时允许 2—8 章。章节数由资料和场景决定。营销增长有依据时优先使用“增长环境与趋势 → 现状与挑战 → 总体方案 → 平台能力 → 实施与服务 → 公司介绍”；缺少相应材料时合并或省略，只有产品背景时不编行业趋势。技术接口文档是能力证据，不应直接成为面客目录。无资料时不会要求用户先上传路径；若已有至少一章有据正文，先交付可编辑初稿，并在对话中点名缺章；用户可补充信息或选择公开检索，再生成新版。所有章节均无有据正文时拒绝空稿，不伪造产品能力。

## 生成逻辑与质量门槛

1. **资料可读性。** 本地支持文件、目录和 ZIP；从 Markdown、TXT、CSV、JSON、HTML、DOCX、PDF、PPTX、XLSX 提取文字，图片仅登记为素材。先清除 HTML 的样式、脚本、代码和明显 PDF 乱码，再截取可读正文，避免 CSS 挤占业务内容。扫描版 PDF 暂无 OCR。
2. **资料权重。** 产品介绍、售前和营销材料优先承载面客叙事；接口、配置等技术材料用于验证能力与边界。内容中台取材先核对项目绑定、可见知识库和已解析文档，再调用 WeKnora `POST /knowledge-bases/{id}/hybrid-search`。检索按企业背景、客户问题、产品能力、实施场景分组；增长售前的背景查询带上增长环境与营销趋势词，协同场景仍查企业背景。每组优先保留最多 4 个 chunk，无结果时换问法重试一次。重复 chunk 只保留一份并标记支持的主题，最后从其他命中中补最多 4 条，总量不超过 20 条。未命中的主题会在结果中明确显示；不会拿其他主题的片段凑数，也不把整库文档原文下载后喂给模型。服务端仍作最终权限校验。
3. **问题与方案对应。** 资料明确写出客户问题时提取原有关系；只给出场景和能力时，可以提出“典型挑战”的候选表述，但保留待确认状态。每组关系都要有痛点、对应做法及两侧原文引文，独立复核是否处于同一场景、做法是否直接回应问题。没有可靠关系时可保留空数组，不能编造配对。
4. **公开资料补充。** 有 `web_search` 且内部证据不足时，可在初稿后由用户选择查询行业或场景背景。查询词不带企业资料原文或客户名；结果最多保留 5 条及 URL、时间、摘要。公开信息只用于行业问题或趋势，不用来证明本企业产品能力、客户收益或交付承诺。
5. **大纲与正文。** 明确提供材料时先展示大纲，可说“第 2 章改为实施路径”“合并第 2、3 章”“就按这个生成”。正文按章调用当前 DSH 模型，一次最多并行三章，按大纲顺序拼接；每章只收到相关证据片段，不再一次请求整稿。若同批三章都遇到模型服务故障，就停止后续请求，避免反复等待。模型主动留空时，插件从已清洗的原文中提取简短要点作为有出处的内部初稿，不把缺失事实补造成承诺；无可用要点的章节仍标为缺口。单份材料的大纲漏写来源编号时，继续使用这份材料的真实来源。模型不可用会报错；全部章节都是占位文案时不交付。模型声明支持 `reasoningEffort: off` 时才关闭思考，未声明时不强传该参数；若模型误报支持，会自动以默认参数重试一次。插件所有模型请求均不指定 `maxTokens`，由 DSH 模型路由与服务商决定输出上限。单章最多等待 90 秒，超时会给出明确错误。自建 OpenAI 兼容路由须在 DSH 中正确配置关闭思考的协议映射；未配置时可能仍受模型自身思考预算影响。输出仍须通过逐字引文和非空稿校验。
6. **交付前阻断与缺口继续。** 引文必须逐字出现在对应来源中，且来源属于该章；公开资料不得作为产品能力章依据，代码、乱码和不可读片段被拒绝。所有章节均无有据正文时停止输出；部分章节未完成时交付明确标注的内部初稿，并在对话中点名缺章、引导补充或公开检索。补充后另存新版，旧版不被静默覆盖。

Word 初稿会先在对话中提供 `.docx` 链接，用户可以打开核对或进入 HTML 编辑页修改；回复“确认并交付”后才展示完整交付链接。用户在初始要求里明确说“不用确认，直接出最终产物”时跳过这一步。Word 的下载文件仍是内部稿，外发需另走外发检查。已授权项目会并行请求 `GET /api/v1/solutions/projects/{id}/memory/recall`，把平台返回的 `block` 原样放入组稿系统提示词；接口未部署、禁用或返回失败时继续生成。未确认的项目记忆不会由插件自动转正。

生成阶段会在 DSH 服务日志输出不含客户正文的阶段耗时、模型请求耗时、输入长度和错误类别，以及服务商提供时的错误码和 HTTP 状态。自动售前入口的证据判断与大纲生成并行执行；模型声明支持关闭思考时优先使用，若服务商以参数错误（如 400 / 1210）拒绝，仅撤去该参数重试一次。遇到真实 400 时可先按日志中的 `stage` 和 `issue` 定位调用阶段；这不等于已确认所有 1210 错误都由思考参数引起。

`wlyd_solution` 的结构化输入必须含 `pain_solution_links`，没有可靠配对时传 `[]`；`wlyd_platform_generate` 必须接收已确认的 `outline_headings`，并核对返回章节与大纲一致。这些是工具契约，不靠提示词单独约束。实现入口见 `src/router.js`、`src/content.js`、`src/source-quality.js` 和 `src/index.js`；人工售前方案抽象出的写作规则见 `guides/presales-writing.md`。

### 版式选择与图表

每份方案先根据业务内容选定一个整体风格：营销增长采用暖纸编辑式；医疗、教育、金融等专业服务采用清晰蓝色网格；技术架构/算力说明采用深色高对比；其他企业方案采用克制红蓝。用户明确指定 `theme` 时优先使用指定主题。同类内容可以复用同一风格，不再按生成次数轮换，也不按章节混用多种底色。方向、选择依据和稳定种子写入 `solution.json`；编辑和外部稿继承这一设计语言。

各页按文字长度、要点数量、步骤、对应关系、图片和真实数值选择主张、能力、流程、证据、关系或图表构图；字号、边距、图标和品牌色统一。五个短步骤尽量整组放在一页，长流程跨页时均衡拆分、连续编号、标清“续”，沿用同一种流程样式。独立的单步内容可以使用里程碑页，多步流程的最后一步不能被误当成独立里程碑。数值图表只取有据数据，不补造数字。

较长的叙述段落采用“材料中可提取的短语标题＋较小的解释文字”卡片；一页两项判断时并排呈现，单项占用固定左右安全边距之间的版心。隐藏来源后，正文会收回原本预留给来源的栏位。`metrics` 大字卡片仅接收同一段逐字引文中相邻出现的标签与数字；年份和未见于引文的数值不作为指标放大。

新稿会依据总体方案、能力或场景正文，在内部稿最多提出两处不同用途的配图位置：关系图或真实产品/场景截图。占位写入 `solution.json`，在 HTML 编辑器中可上传 PNG/JPEG 替换，内部 Markdown/Word 同步说明；外部预览与外发文件省略未替换的占位，外发检查会列出其章节位置并允许确认省略。占位不是已交付图片，也不代表产品实际界面。

`chart` 内容块只接受 2—6 个同单位数据点，支持类别比较（`bar`）和按时间排列的趋势（`line`）。标题、类别、数字、单位及逐字引文保存在 `solution.json`；自动生成时还核对引文是否属于该章原始资料。任何数字或标签不在同一段引文中，就丢弃该图表。资料只有定性描述时使用流程或问题—做法关系图，不补造统计。直接调用 `wlyd_solution` 的调用方仍须核对传入的来源路径确实指向原始材料。

HTML 负责图形表达；Markdown 和 Word 把同一图表数据输出为可审阅的表格并保留来源。HTML 编辑器可改图表标题、单位、标签和数值；改动数据后，所有格式都标记“数据待确认”，原始引文继续保留供审核。平台生成的纯 Markdown 若没有可核对的原始数字引文，不会自动转成图表。
外部稿保留已核实的图表与数值，但去除内部来源路径和原文；数据被编辑后尚未核对时，外发检查会阻止生成外发文件。

## 面客话术与事实边界

面客写法参考 [可核对的话术指纹](guides/voice-fingerprint.md)：该版本只从一份获认可的人工 CallWan 成稿中抽取可观察写法，保留来源范围和不确定性，不把样本里的产品事实迁移到其他项目。组稿要求封面或开篇有产品定义，能力按使用者、动作和可见结果解释。生成后会提示副标题或章节导语中的抽象表达；提示不会把有据章节改成空稿，也不代替业务复核。

| 规则 | 处理方式 |
| --- | --- |
| 以客户能理解的收益、场景和步骤表达 | 生成提示和写入 JSON 前的措辞转换共同约束标题、导语与正文；“待人工复核”等内部制作语改为面客说法 |
| 基于事实精炼表达 | 标题点出对象与主题；开篇交代产品是什么、适合谁。挑战按“问题名：具体表现”写清发生环节与业务影响，再写对应做法。正文多用短句，但不能删去场景、因果、适用条件、来源或不确定性；避免空泛套话 |
| 客户痛点不是已核实事实时 | 用“典型挑战”“可能”等自然限定，制作提示另存为可编辑校对项，保留 `inferred`、`public_unverified`、`user_unverified` 等依据状态 |
| 痛点与做法前后对应 | 每条关系同时保存两侧来源；不能从一个行业痛点直接推出本产品一定解决，也不能把功能清单冒充客户问题 |
| 不升级声明强度 | 不凭空写价格、指标、资质、案例、效果保证、合同或实施周期；没有证据的收益只能写为待验证目标 |
| 保留可追溯性 | 原文引文、来源路径和证据状态不做“润色”；所有导出从同一 `solution.json` 渲染 |
| 封面与演示页面 | 封面只放主题和必要抬头，目录只列短章名；章节过渡页只放短标题及可选短句，长引言留在正文；主标题、章节标题、内容标题和注释有层级，长内容拆页并防止越界 |

这里的“面客措辞”也是生成约束，但不能代替正式审批。内部稿保留来源；在 HTML 中点击“外部稿预览”可预览去除来源字段后的面客版本。只有完成外发检查并生成独立外发文件后，才可按确认的用途使用。客户事实、名称、商务信息、图片授权和适用版本仍需人工核对。

## 对话附件同步到内容中台

在 DSH 输入框附上文件，然后发送“同步到内容中台”；也可以写“同步到内容中台，项目=项目名称，知识库=知识库名称”。唯一可用目标可直接选定，有多个项目或绑定知识库时，插件先在输入区让用户选择。该入口直接调用上传工具，不先调用模型来猜上传动作。

XLSX 使用单元格解析器转为 Markdown：保留工作表名、原行号、中文、百分比及已缓存的公式结果，不执行公式；DOCX/PDF/PPTX 同样先提取文本。Solution 接口不接收原 XLSX，只接收转换后的文本。旧 XLS/DOC/PPT 尚未支持。每轮最多 10 个文件，单文件最多 20MB；过大、不可读或不支持的文件会逐项说明，不静默称为成功。只读取当前会话提供的附件，上传前再核对项目绑定；中文文件名通过标准 multipart 表单保留。

后台返回 202 表示“已接收”，插件继续查询解析状态；只有 `completed` 才显示“解析完成”。部分文件失败时逐项显示成功、失败或解析中。模型参数错误与上传 API 的 HTTP 状态、错误码、request ID 分别定位。

外发检查中的“待与贵方确认”“修改记录”等措辞提示会显示章节、文字片段和定位入口；业务人员可以逐项核对或一次确认全部提示后继续外发。确认与当前源稿版本、规则摘要绑定，写入内部外发记录。来源证据不会因此自动改写成已核实事实。

## 安装与配置

前提：Node.js 22+、可正常启动的 DSH、当前会话可用的模型服务；安装依赖时能访问 npm 软件包源。将分发包 `wlyd-dsh-presales-solution-0.9.28.tgz` 放到本机，执行：

```sh
dsh plugin --profile web add "/绝对路径/wlyd-dsh-presales-solution-0.9.28.tgz"
dsh plugin --profile web list
dsh web
```

若 Web 已启动，先在该终端用 Ctrl+C 停止，再重新运行 `dsh web`。DSH 仓库开发环境可将上述 `dsh` 换成 `pnpm dsh`。插件通过 `cordis.patch.yml` 注册到 web profile，安装后应在列表中看到 `@wlyd/dsh-presales-solution@0.9.28`。浏览器使用启动终端给出的地址和认证方式；直接把未认证的 `127.0.0.1` 结果链接粘到另一个浏览器，可能得到 401。

内容中台由 **运行 DSH 的服务端**配置：

| 环境变量 | 用途 |
| --- | --- |
| `WLYD_PLATFORM_BASE_URL` | 内容中台地址；未设置时使用代码内默认地址 |
| `WLYD_PLATFORM_EMAIL` / `WLYD_PLATFORM_PASSWORD` | 平台登录账号 |
| `WLYD_PLATFORM_TENANT_ID` | 当前租户 |
| `WLYD_KNOWLEDGE_PROPOSAL_URL` | 可选：知识修改的待审核提交接口 |
| `WLYD_KNOWLEDGE_API_TOKEN` | 可选：该接口的服务端令牌 |

内容中台检索会为企业背景、客户问题、产品能力与实施场景分别构造查询；某类没有可用命中时用另一种问法重试一次。每类优先保留最多 4 个片段，再用最多 4 个名额补充分数靠前的其他结果，整体不超过 20 个。重复 chunk 合并并记录其支持的主题；最终命中数和缺失主题显示在结果摘要中。检索请求限定在当前项目绑定知识库及解析完成的文档中；每个证据来源保留知识文档 ID、chunk ID、标题、位置、召回分数和主题标签。正文只收到命中的片段，避免把无关文档全文送入组稿上下文。每轮在 `presales-runs/<运行目录>/research/retrieval-snapshot.json` 保存查询、主题覆盖和命中快照，供复核定位。若接口返回错误，会显示 HTTP 状态、后端错误码/信息和 request ID，便于后端排查；没有命中时明确报错，不静默改为全文下载。

凭证仅放服务端环境或 `$DSH_HOME/.env`，不要写入对话、前端、分发包或 Git。接收方需要自己的合法账号与项目授权；租户测试账号的联调结果不代表每位用户都有相同权限。

### 最短验证路径

在 DSH Web 新建会话输入“给我一份 CallWan 的产品售前解决方案”。应看到资料检索和正文生成；若无权限或模型配置，应收到具体错误，而不是空白幻灯片。要验证本地材料入口，可准备一份包含产品能力和适用场景的 Markdown 文件，然后输入 `用材料=/实际绝对路径 生成售前解决方案`。先修改或确认大纲，再检查最终每章是否有可读正文、依据与适用边界。

## 产物、编辑与知识同步

每轮产物独立保存在 DSH 会话工作目录的 `presales-runs/<时间>-<随机码>/`：

| 路径 | 作用 |
| --- | --- |
| `analysis/materials.json`、`analysis/corpus.md` | 材料清单、提取状态与可读文字 |
| `research/public-sources.md` | 使用公开检索时的 URL、时间与摘要 |
| `solution.json` | 唯一结构化源稿，含稳定内容 ID、来源与编辑版本 |
| `solution.html` | 16:9 可演示、可在授权入口编辑的 HTML；浏览器可打印为 PDF |
| `solution.md`、`solution.docx` | 与当前 JSON 同步生成的阅读和交付稿 |
| `solution.versions/` | HTML 每次保存后的历史快照 |
| `solution.knowledge-proposals/` | 涉及事实的编辑所提交的待审核记录 |

结果消息提供结构预览、内部 HTML 编辑入口和 Word / Markdown / JSON 下载。先完成 DSH Web 认证，再在同一浏览器打开。对话附件会直接用于生成；同步到内容中台需选择正确项目，失败时保留已生成稿。内部 HTML 默认展示来源，点击“外部稿预览”进入独立预览及外发检查；内部 JSON 与证据不随外发文件下载。HTML 编辑保存后生成新修订版，并从 JSON 重渲染三种内部格式；并发旧窗口会提示刷新，避免覆盖新版。离线双击 HTML 只能预览和打印；在 Word 或 Markdown 中直接修改不会反向同步。

编辑产品事实时可勾选“提交知识审核”。插件保存变更和来源，并尝试发到配置的审核接口；未配置时状态为 `awaiting_knowledge_api`，**不代表已经入库**。知识事实须确认后再入库，方案措辞修改不会自动覆盖知识。接口约定见 `guides/knowledge-api-contract.md`，历史记录可用 `node bin/submit-knowledge.mjs "/方案所在目录" solution` 重试。

HTML 设计规则见 `guides/slide-design.md` 和随包 Skill `skills/wlyd-presales-html-ppt/SKILL.md`。渲染器按内容选择主张、问题与做法、流程、能力、证据等页型；图标、定性关系图和有据数据图由插件自身生成。设计方法吸收了 `ui-new` 的层级/对比度检查和 `ui-ux-designer` 的设计令牌/阅读路径判断，已转成插件内的页型规则、主题色、控件状态和自动测试，接收方无需另外安装这两个 Skill。主题文字对比度与 44px 翻页控件由测试守护；真实观感、极端长内容和打印效果仍应逐页复核。当前没有可编辑 PPTX 导出；PDF 是浏览器打印能力。

Design Master 与 [Huashu Design](https://github.com/alchaincyf/huashu-design) 的售前适配规则分别位于 `skills/wlyd-presales-design-master/SKILL.md` 和 `skills/wlyd-presales-huashu-design/SKILL.md`。插件在 `apply()` 中用 DSH 的 `ctx.skills.register(...)` 注册；确定性生成请求在证据判断、大纲、整稿与单章重试时主动读取所需 Skill 正文和设计资源，并把规则注入模型上下文；JSON 的 `skillExecution` 记录阶段、哈希及目录或随包读取状态。DSH 目录读取异常时会用随包规则继续生成并记录原因，不能把规则读取失败伪装成模型调用失败。整稿风格和页型选择还由 `src/visual-plan.js`、`src/html.js` 执行。`injected` 仅证明规则进入请求，最终效果仍须检查成稿。上游 Huashu Design 的动画、PPTX 与视频脚本没有并入本包，不能声称执行这些功能。

## 工具与边界

| 工具 | 职责 |
| --- | --- |
| `wlyd_ingest` | 读取本地材料，提取可读文字和图片清单 |
| `wlyd_solution` | 验证结构化方案并写出 JSON、HTML、Markdown、DOCX |
| `wlyd_platform_setup` | 创建项目、绑定知识库并上传 1—10 个文件 |
| `wlyd_platform_upload` | 向已绑定知识库上传工作区文件并查询解析状态 |
| `wlyd_platform_generate` | 按已确认大纲使用平台资料生成 |

上传时文本文件直接上传，DOCX / PDF / PPTX 先提取为 Markdown；图片和 ZIP 不作为平台上传件。远程链接和聊天附件尚未作为本地材料入口接入；扫描 PDF 暂无 OCR。分发包不包含材料、会话数据或凭证。手工修改 `solution.json` 后可用 `bin/render.mjs` 离线重渲染，但该操作不产生 HTML 编辑版本，也不提交知识审核。

## 内部稿与外部稿

生成和编辑的是内部稿，HTML 默认显示来源；右下角“外部稿预览”打开独立的面客预览。预览尚未批准外发。在预览中确认结构、口径、受众、分发范围、事实基线、版本及逐项清理检查后，系统才生成独立的外发 HTML、Markdown、Word。内部 JSON、原文引文和审核记录不会进入外发文件；原内部稿和已生成的外发快照不会被覆盖。

规则文件可以修改并回退，使用方法见 [内部稿与外发稿规则](guides/external-release.md)。扫描只能识别部分敏感内容；客户名称、案例、图片、商务条件和声明强度须由确认人核对。本地确认记录不等于企业正式审批。

## 排错与验收

| 现象 | 先检查 |
| --- | --- |
| 没有 `/presales` | 是否安装到 `web` profile、列表有无插件、Web 是否重启；空白会话先用普通文字触发 |
| 知识库不可读或上传失败 | 平台账号、租户、项目绑定、文档解析状态和当前账号权限；服务端授权不能靠插件绕过 |
| 方案为空或大多是待确认 | 当前模型是否可用，材料是否有可读正文；若提示模型调用失败，检查自建路由的 `reasoningEfforts` 与 `compat.thinkingFormat`。0.9.9 会先清洗混合检索片段中的 HTML，再按可引用正文计算命中；纯样式片段不占名额。全占位会阻断交付；部分缺章会在对话中提示补充或公开检索 |
| HTML / 下载链接返回 401 | 在同一浏览器完成 DSH Web 认证，并确认 Web 进程仍运行 |
| `awaiting_knowledge_api` | 方案已保存，知识审核接口尚未配置或尚未完成提交 |
| `Cannot read properties of undefined (reading 'prepare')` | DSH 宿主工具运行时需包含 `packages/core/tools/src/index.ts` 的调度器标识修复；只重装插件无效 |

在插件源码目录执行最小回归与打包：

```sh
npm ci
node --test test/*.test.mjs
node test/selftest.mjs /tmp/dsh-presales-selftest
mkdir -p dist
npm pack --pack-destination dist
```

自动测试和渲染自测只覆盖代码契约；真实账号权限、模型质量、公开检索准确性、复杂 PDF 和客户可用性仍需在目标 DSH 环境验收。`npm pack` 包含 README、源码、指南、Skill 和 DSH 挂载声明，不包含 `node_modules`、客户材料或密钥。
