# 售前方案设计判断

这是对 Design Master 的设计方法做的售前场景适配。原 Skill 不随本包复制；本规则与渲染器共同执行。

1. **先定整稿方向。** 看产品、受众、材料和品牌后，整份方案只选择一套主题令牌。颜色、字体、间距、图标笔画保持一致；章节之间变化的是构图和信息密度，不换一整套颜色。
2. **先定阅读层级。** 页标题告诉客户本页讲什么；问题或能力小标题用短语；正文用正常字号说明场景、动作和影响。不能把长段落放大为主标题，也不能让标题、解释和来源同权重。
3. **痛点页讲深。** 每个有依据的痛点依次呈现“短问题名 → 工作中可见的表现 → 造成的麻烦”。可用大标题、分组小标题和短正文分两页讲；关键词可以使用统一的强调色，整段正文不能全部加粗。
4. **方案页讲做法。** 只用短标签回扣已经解释的痛点，主要空间留给对应机制：谁使用、在哪一步操作、系统怎样承接、留下什么可见结果。多个方案须保持编号和对应关系，不重复大段痛点。
5. **内容决定页型。** 单一短结论用主张页；并列问题用分组卡片；过程用顺序轨道；问题与做法用对应图；可核对数字用图表或大字指标；真实截图用图文并置。没有数字或图片就不用假图占位。
6. **检查边界和状态。** 页内左右版心一致，来源隐藏后正文不偏移；长文字先分页，仍放不下才在页内滚动。内部校对信息与对外正文分开。桌面、窄屏和打印页都要检查可读性。

运行时的固定设计选择由 `src/visual-plan.js`、`src/html.js` 执行；写作规则由 `src/writing-rules.js` 执行。完整验收清单见 `guides/slide-design.md`。调用此 Skill 可以辅助修改或审稿，但是否在 DSH 对话中被模型主动加载，须以实际会话轨迹验证。
