# 内容到页面的设计契约

参考 Design Master 的层级、品牌令牌、排版与内容关系判断，适配客户售前演示。生成 JSON 时执行以下规则，渲染器执行可验证约束。

## 信息优先级

- 页标题：本页讲什么，建议 8—24 字。不塞入一整段背景。
- 并列观点使用 para{label,title,text,emphasis}。label 是可选的 2—8 字类别；title 是 4—18 字具体主张；text 用 2—3 句解释对象、动作、影响，通常 50—110 字；emphasis 是 text 中已出现的 1—3 个重点词，不造新结论。
- 每个观点独立，不把四个不同问题挤入一段。不要用短句数量代替信息量。
- 例如痛点可写“线索分散 / 多渠道咨询难统一跟进”，正文解释评论、私信、表单的来源和承接状态为何难以统一。仅在来源支持时使用这个示例。
- 痛点章详细讲具体表现和后果；方案章以短标签回扣痛点，把主要篇幅留给具体做法与使用结果。

## 内容关系与页面

- 并列 2—4 个观点：卡片。卡片标题与说明拉开字号和字重；重要词使用整稿强调色。
- 连续业务动作：steps；同一模块续页保持编号、字体和构图，不把最后一步改成孤立大字。
- 方案组成和职责：架构关系或分层说明；没有关系数据时不凭空画箭头。
- 痛点到做法：对应关系图或对照表；编号前后保持一致。
- 来源中真实、口径一致的数据：metrics/chart；强调数据并解释含义，禁止拼接年份或页码制造指标。
- 产品操作与能力：真实截图或可替换的截图位置；记录需要的界面、要标注的动作与展示目的。占位不是产品截图，禁止伪造界面。

## 整稿一致性

- 依据内容先定风格，再选匹配的整稿配色。新生成可更换配色，保存后不因编辑或重渲染改变。
- 一份方案只有一套主色、强调色、字体、版心和图标笔画。版式随内容变化，不逐页换色。
- 封面只保留方案名称、清晰产品定位与必要署名；目录独立。
- 页标题、正文、页脚共用固定左右版心。隐藏来源只去掉来源，不留下空列或改变正文起点。
- 正文不得整段加粗放大；短主张页只允许真正的短句，长文使用标题加正常字号说明。
- 桌面、窄屏与打印都检查边界；元素不能溢出，来源与内部校对信息不得覆盖面客正文。
