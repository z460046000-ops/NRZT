# 售前方案 HTML 幻灯片

适用范围：本插件生成的 `solution.html` 及其版式改进。内容真源始终是 `solution.json`；文字或图片要通过 DSH HTML 编辑入口保存，再同版重生成 Markdown、HTML、DOCX。

## 设计判断

1. 先看读者要理解的结论和证据，再决定页面类型。封面只呈现主题和必要抬头；目录、章节、单一论点与来源、痛点对应做法、图片与表格应有不同层级，不用同一种卡片铺满全稿。
   章节按材料建议约 3—6 章。用户只说产品名时直接生成可复核初稿；用户明确要调整结构或走材料导入流程时，再展示大纲供调整。目录按最终标题和顺序呈现。
2. 使用 16:9 页面和明确的安全区。任何文字、图片、表格、卡片、控件都不得越过 HTML 页面或单页画布边界；长内容先拆页，超长单词与路径换行，仍放不下时在区域内滚动，不允许被静默裁掉。中文正文在 1280×720 画布上原则上不小于 16px。
3. 企业方案封面可以用深色背景建立识别，正文使用浅底、深色文字、少量企业强调色；红色用于状态或重点，蓝色用于对应做法。其他主题也须保证正文对比度。
4. 一页只强调一条核心判断。目录按内容长度排布；段落、列表、表格和图片按适合阅读的密度分页。不要为了填满页面伪造数值或装饰素材。
5. 客户痛点与解决办法沿用同一 P 编号。两侧材料依据清楚可见；不足之处标待确认，不能把推断写成已证实的事实。
6. 真实截图保持原比例，说明其证明的内容；页码、键盘翻页、打印和窄屏预览都必须可用。
7. 标题按封面主标题 → 章节标题 → 内容页标题 → 卡片小标题递减；字号、字重和间距要让主次一眼可辨，不能把大小标题排成同一级。
8. 封面只呈现方案标题、副标题、企业和必要抬头。目录放独立页，不把大纲塞进封面，也不放“待人工复核”等内部状态话术。
9. 先把标题、导语、正文、步骤和结尾写成客户能直接阅读的话语，再用同一 JSON 渲染各格式。证据不足用“待与贵方确认”，逐字引文和来源不能润色改写。
10. 生成前检查正文覆盖率。整稿只有占位文案时停止交付；资料或模型不足应说明缺口，不把空白页包装成完成的方案。
10. 依据内容选择主张、问题→做法、流程、能力清单或证据截图页；流程节点和连接线只表现已有顺序/对应关系，指标图只使用材料中真实数值。

## 交付检查

- 检查封面、目录、痛点、对应做法、普通正文、图片和打印页；逐页测量横向、纵向溢出，长标题与长材料路径不能被裁切或越界。
- 检查键盘方向键、PageUp/PageDown、空格、Home/End、上一页/下一页，以及输入框获得焦点时不会误翻页。
- 检查页码控制旁的来源显示切换：来源注释、痛点依据与表格依据列可一起隐藏和恢复；切换不改变源稿中的证据。
- 从 HTML 编辑保存一次后，核对 `solution.json`、Markdown、HTML、DOCX 的版本与内容一致；事实变更只提交知识审核。
- 结果消息须有可见的结构预览、明确的编辑入口和已认证的源稿下载地址；本地相对文件路径不能当浏览器链接。

## 来源与边界

本规则为售前插件的原创适配，参考 Codex `impeccable` 的层级检查、`html-design-master` 的图文节奏、`guizang-ppt-skill` 的语义页型，以及 [SkillHub html-ppt-skill 2.3.0](https://skillhub.cn/skills/user_e9af5021/html-ppt-skill) 的视口安全与排版检查思路；未复制其模板或源码。它不提供 WorkBuddy `tencent-pptx`、Ardot 或可编辑 PPTX 导出。
