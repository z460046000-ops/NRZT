# 售前方案 HTML 幻灯片

适用范围：本插件生成的 `solution.html` 及其版式改进。内容真源始终是 `solution.json`；文字或图片要通过 DSH HTML 编辑入口保存，再同版重生成 Markdown、HTML、DOCX。

## 设计判断

1. 先看读者要理解的结论和证据，再决定页面类型。封面只呈现主题和必要抬头；目录、章节、单一论点与来源、痛点对应做法、图片与表格应有不同层级，不用同一种卡片铺满全稿。
   章节按材料建议约 3—6 章。用户只说产品名时直接生成可复核初稿；用户明确要调整结构或走材料导入流程时，再展示大纲供调整。目录按最终标题和顺序呈现。
2. 使用 16:9 页面和明确的安全区。任何文字、图片、表格、卡片、控件都不得越过 HTML 页面或单页画布边界；长内容先拆页，超长单词与路径换行，仍放不下时在区域内滚动，不允许被静默裁掉。中文正文在 1280×720 画布上原则上不小于 16px。
3. 企业方案封面可以用深色背景建立识别，正文使用浅底、深色文字、少量企业强调色；红色用于状态或重点，蓝色用于对应做法。其他主题也须保证正文对比度。
4. 一页只强调一条核心判断。目录按内容长度排布；段落、列表、表格和图片按适合阅读的密度分页。不要为了填满页面伪造数值或装饰素材。
5. 客户痛点与解决办法沿用同一 P 编号。两侧材料依据清楚可见；不足之处标待确认，不能把推断写成已证实的事实。
6. 真实截图保持原比例，说明其证明的内容；页码、键盘翻页、打印和窄屏预览都必须可用。
7. 标题按封面主标题 → 章节标题 → 内容页标题 → 卡片小标题递减；字号、字重和间距要让主次一眼可辨，不能把大小标题排成同一级。
8. 封面只呈现方案标题、副标题、企业和必要抬头。目录放独立页，不把大纲塞进封面，也不放“待人工复核”等内部状态话术。
9. 内部稿由同一 JSON 渲染各格式，保留证据和待确认状态；外发稿从指定修订版按规则派生，话术面向客户，不能包含内部来源路径。证据不足先留在内部稿处理，不能把待确认改写成已实现。详见 `guides/external-release.md`。
10. 生成前检查正文覆盖率。整稿只有占位文案时停止交付；资料或模型不足应说明缺口，不把空白页包装成完成的方案。
11. 依据读者要理解的关系选择页面构图：单一短观点用大字主张页；2—4 个简短能力点用疏朗分组；5 个以上或长要点用单列清单；4 步以上流程用错列节奏，1—3 步可横排或纵排；有图像和依据时采用图文并置，只有图像时扩大图片；长叙述先提炼一句主张，再将正文与依据分组。不能只给同类内容换左右位置。
12. 页面之间交替信息密度和视觉重心：主张页留白，能力页分组，流程页展示方向，证据页放大真实素材，图表页突出数据关系。整份方案保留同一品牌色、字体层级、页边距与依据规则；变化服务于内容，不用装饰图形填空。
13. 同一 JSON 重新渲染须稳定，不随机换版。渲染器优先按内容长度、要点数量、步骤数和依据是否存在选择构图；在语义相同且条件相近时，再用稳定规则避免相邻页重复。
14. 比较图和趋势图须由同一段可核对原文支持类别、数值和单位；趋势点按时间排序。资料不足时使用定性关系或流程，不做假数据图。
15. 运行时从已保存的 P 编号、步骤和能力要点确定性地绘制对照关系、流程轨道和能力关系图；图标只标识章节或节点的既有语义，不承载额外事实。HTML 图形须可在源稿修改后重建，Markdown/Word 继续保留相同文字与顺序。
16. 以客户阅读顺序决定一页的焦点：标题讲结论，图形讲对应或顺序，来源放辅助层。依 `guides/slide-design.md` 的内容—页型映射选择构图；主题令牌维持统一的色彩、字体与间距，普通文字与背景对比度至少 4.5:1。过长内容退回文字排版或拆页，不为了“好看”删事实。
17. 无图无数值的材料仍应区分画面：短引言＋短要点用左右强弱对比；短引言＋长要点用整宽信息带；三个段落用一条主张加双列说明；单一步骤用里程碑。只在内容结构支持时使用对应页型，不能把长列表误判为一页大字主张。
18. 一份方案先按内容选一个统一风格：营销增长 `paper`，专业服务 `signal`，技术架构/算力 `night`，其他企业业务 `redline`。明确指定主题时优先使用该主题。同类内容可以同风格；不按次数轮换，不按章节换多套底色。风格、依据和种子写入 JSON，编辑和外发继承。
19. 页面多样性来自主张、清单、图文、流程与图表的内容组织；字体、字号角色、配色、网格与图标笔画统一。同一个多步流程的末节点不能变成独立里程碑。五个短步骤优先整组一页；跨页时均衡拆分、编号连续、标清“续”、页型一致。
20. 当有据正文适合图解或产品截图但本轮没有图片时，内部稿最多标出两处具体配图位置，说明要解释的业务环节和所需素材；编辑器可替换真实图。未替换的占位不进入客户预览和外发文件，外发检查列出省略位置。不得用示意图冒充实际产品界面。

## 交付检查

- 检查封面、目录、痛点、对应做法、普通正文、图片和打印页；逐页测量横向、纵向溢出，长标题与长材料路径不能被裁切或越界。
- 检查键盘方向键、PageUp/PageDown、空格、Home/End、上一页/下一页，以及输入框获得焦点时不会误翻页。
- 检查页码控制旁的来源显示切换：来源注释、痛点依据与表格依据列可一起隐藏和恢复；切换不改变源稿中的证据。
- 从 HTML 编辑保存一次后，核对 `solution.json`、Markdown、HTML、DOCX 的版本与内容一致；事实变更只提交知识审核。
- 图表数据在 HTML 编辑后标待确认；Markdown/Word 输出同一组数字、单位与原始依据，不能只改图形不改源稿。
- 按层级、对比度、排版、间距、控件状态、边界六项复核；上一页/下一页等控件可见焦点，最小点击高度 44px。静态测试只能验证规则和对比度，仍需逐页查看实际视觉效果。
- 结果消息须有可见的结构预览、明确的编辑入口和已认证的源稿下载地址；本地相对文件路径不能当浏览器链接。
